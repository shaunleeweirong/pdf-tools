You can password protect a PDF for free right in your browser, without downloading Acrobat or any other software. The [Protect PDF tool](/protect-pdf) encrypts the file with AES-256 on your device before you ever download it, so the password-protected copy is ready in seconds and your original file never goes anywhere.

## How to password protect a PDF without Acrobat

1. Open the [Protect PDF tool](/protect-pdf).
2. Click **Choose file** (or drag your PDF onto the page).
3. Type a password, then type it again to confirm.
4. Click **Protect**.
5. Download the encrypted PDF.

That's it. The process takes a few seconds for most files. You don't need an account, and nothing is uploaded to a server.

If you're on a phone, the same steps work in any mobile browser. The tool runs in-browser on iOS and Android without requiring an app.

## What encryption does a PDF password actually use?

The tool encrypts your file with [AES-256](https://en.wikipedia.org/wiki/Advanced_Encryption_Standard), the same cipher used by banks, hospitals, and government agencies. AES-256 is specified as the encryption standard in [PDF 2.0 (ISO 32000-2:2020)](https://www.iso.org/standard/75839.html), the current PDF specification.

The cipher itself has no known practical weaknesses. The only realistic way to crack a properly encrypted PDF is to guess the password, which is why your password choice matters more than any other factor. A 12-character mix of letters, numbers, and symbols is computationally safe against brute-force attempts for the foreseeable future. A single common word is not.

Older PDF tools used RC4 or 128-bit AES, both weaker standards. If you're opening a protected PDF that was created years ago, it may use one of these older ciphers.

## User password vs permissions password: which one do you need?

PDF encryption has two distinct password types:

- **User password (open password):** The recipient must enter this password to open the file at all. This is what most people want when they say "password protect a PDF."
- **Permissions password (owner password):** The file opens without a password, but certain actions (printing, copying text, editing) are restricted. This only makes sense when you're distributing a document you want people to read but not modify or copy.

For tax returns, contracts, medical records, or any document with personal information, use a user password. A permissions password on its own offers little protection because many PDF readers allow you to ignore or bypass permissions restrictions.

## Will the file get bigger after adding a password?

Barely. Encryption adds a fixed overhead of roughly 1 KB regardless of how large the PDF is:

| File | Before | After | Change |
|---|---|---|---|
| 20-page text report | 23.5 KB | 24.6 KB | +4.8% |
| 6-page image deck | 913.4 KB | 914.4 KB | +0.1% |

On a large file, the overhead is invisible. On a very small file it's a slightly larger percentage, but still under 2 KB in absolute terms. Password protection won't push a file over Gmail's or Outlook's 25 MB attachment limit.

## Can I remove the password later?

Yes. If you need to share a previously protected file with someone who can't enter the password, use the [Unlock PDF tool](/unlock-pdf). Enter the current password, and it returns an unencrypted copy you can share or edit freely.

In testing, removing the password returned the file to within a few bytes of its original size, so the round trip is effectively lossless.

## When to use a PDF password (and when not to)

PDF passwords make sense for:

- Tax documents, payslips, and financial records sent over email
- Contracts or NDAs you're sending to a specific recipient
- Medical records or any file with personal identification
- Any PDF you want to ensure only an intended recipient can open

A password is less useful when you need to share a file with many people at once, since you'd have to give every recipient the password through a separate channel. In that case, a shared folder with access controls (Google Drive, Dropbox) often works better.

Also worth knowing: password protection is not a substitute for secure transmission. If you email a protected PDF and the email itself is intercepted, the attacker still has the encrypted file. Send the password through a different channel, such as a text message, rather than in the same email as the PDF.

## A quick note on password managers

The one practical downside of password-protecting PDFs is that you have to remember (or store) the password. If you lose it, there's no recovery option. A [password manager](https://en.wikipedia.org/wiki/Password_manager) like Bitwarden, 1Password, or your browser's built-in manager is the simplest way to keep track without writing it on a sticky note.
