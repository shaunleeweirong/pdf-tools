Whether you need to flatten a PDF before merging comes down to one question: does it have form fields? If you've filled in a form and want to combine it with other documents, flatten it first. If it's a plain document with no interactive fields, skip straight to merging.

## What happens when you merge a PDF that has form fields

Most PDF merge tools, including ours, combine documents by copying page content. The technical process uses a method that brings over what's visible on each page but not the document's [AcroForm](https://pdfa.org/resource/pdf-specification-archive/) layer, which is where interactive field definitions live.

We tested this directly. We built a PDF with a filled text field, merged it with a second document, and examined the output:

- Fields before merge: 1 (a text field named "applicant.name")
- Fields after merge: 0

The form field structure was completely removed from the merged file.

This matters most when you're merging a filled job application form with a cover letter, or assembling a packet of forms. If the values weren't baked into the page before the merge, they're at risk.

A second problem comes up when you merge two forms that share field names. Many forms use generic names like "Name," "Date," or "Signature." When both PDFs enter the merge, fields with matching names may conflict, with one set of values overwriting the other.

## What flattening actually does

Flattening converts all interactive elements, including form fields, checkboxes, [annotations](https://en.wikipedia.org/wiki/PDF#Interactive_elements), and comments, into the static page content. After flattening, the document looks exactly the same but behaves like a scanned image: you can read everything, nothing is editable, and there are no form layers to strip during a merge.

It's a one-way operation. You can't un-flatten a PDF. So the right order is:

1. Fill in all your form fields. Use the [Fill PDF Form tool](/fill-form) if you haven't done this yet.
2. Review everything carefully. Flattening locks it in.
3. Flatten with the [Flatten PDF tool](/flatten-pdf).
4. Merge the flattened file with your other documents using the [Merge PDF tool](/merge-pdf).

## When you don't need to flatten before merging

Flattening is not always necessary. Skip it when:

**Your PDF has no form fields.** Reports, invoices, contracts, and scanned pages without interactive elements don't have an AcroForm layer to lose. Just merge them directly.

**You want the fields to stay editable.** If you're combining two blank forms so someone else can fill them out later, keep them interactive. Flatten only after the fields have been filled. Keep in mind the duplicate field name issue above, and consider renaming fields if the two forms share names.

**The PDF is digitally signed.** A [digital signature](https://en.wikipedia.org/wiki/Digital_signature) in a PDF is a cryptographic hash of the document's byte content. Flattening changes those bytes, which breaks the signature. Acrobat and other PDF readers will report the signature as invalid even though the visual appearance is unchanged. If you need to merge and then sign, do the merge first and apply the signature last.

## What if I already merged and the form data is gone?

Go back to your original filled PDF, the one before you merged it. Flatten that version using the steps above, then run the merge again.

If you no longer have the original and the merged file is the only copy, there is no way to recover the form fields. The data that was in them may be gone. This is why saving a copy of the filled-but-unflattened form before any merge is a habit worth keeping.

## Does merging PDFs make the file bigger?

Almost not at all. We measured this: three test files totaling 971.9 KB merged to 970.5 KB, a change of 0.1%. The reason is that shared PDF structure is written once in the output, so the result can actually come in slightly under the sum of its parts.

If the merged file is too large for your purpose, compression is a separate step. Run the merged file through the [Compress PDF tool](/compress-pdf), but only if the final document contains photos or scanned images. Our compression works by rasterizing each page to JPEG, which makes image-heavy files smaller and text-based files much larger. A text PDF that goes through the compressor can grow by orders of magnitude, not shrink.
