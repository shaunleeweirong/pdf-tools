You can merge PDFs in Google Chrome right now, without installing an extension and without uploading your files to any server. Open our [Merge PDF tool](/merge-pdf) in a Chrome tab, add your files, and the merge runs entirely inside your browser. Here's what you need to know about each approach.

## Does Chrome have a built-in PDF merger?

No. [Chrome's built-in PDF viewer](https://support.google.com/chrome/answer/6213030) lets you open, zoom, rotate, print, and download PDFs. That's it. There is no "combine" or "merge" option in the viewer's toolbar, and there is no setting hidden in Chrome flags that enables one.

This surprises a lot of people because Chrome handles PDFs so smoothly. But the viewer is read-only. To combine two or more files, you need something extra, either a web-based tool or an extension.

## The fastest way to merge PDFs in Chrome

The quickest option is a browser-based tool that opens in a regular tab. No extension, no download, no account. Here's how:

1. Open the [Merge PDF tool](/merge-pdf) in Chrome.
2. Click **Add files** or drag your PDFs into the drop zone.
3. Drag the file cards to set the order you want.
4. Click **Merge** and wait a moment (most files finish in under a second).
5. Download the combined PDF.

That's it. Chrome treats the tool like any other website. You don't need to change any browser settings or grant any special permissions.

## Can I merge PDFs in Chrome without uploading them?

Yes, and this matters if your files are confidential. Tools that rely on server-side processing send your files to a remote computer, merge them there, and return the result. Tools that use client-side JavaScript, like [pdf-lib](https://pdf-lib.js.org/), run the entire operation inside your browser tab using your own CPU and memory.

Our Merge PDF tool works entirely in your browser. The files are read from your disk into browser memory, merged using JavaScript, and the output is handed back to you as a download. Nothing goes over the network.

If you're ever unsure whether a tool uploads your files, open the browser's developer tools (F12), go to the Network tab, and watch for outbound requests after you add a file. A true client-side tool shows nothing there when you load a PDF.

## What about Chrome extensions?

There are several Chrome extensions for merging PDFs. They work, but they come with trade-offs:

- Installing an extension requires you to click "Add to Chrome" and grant it access to your files, sometimes to every site you visit.
- Extensions update automatically, and new versions can request additional permissions.
- A tab-based tool has none of these downsides. It runs like any other website, under the same security model your browser already applies to every page you load.

If you only need to merge PDFs occasionally, a tab-based tool is simpler and there's nothing to manage afterward.

## Will the merged file be larger than the individual files?

No, and often marginally smaller. When our Merge PDF tool combined three PDFs totaling 971.9 KB, the output was 970.5 KB, a 0.1% decrease. Shared PDF structure is written once in the output, which accounts for the small reduction.

What this means in practice: if your files add up to 19 MB, the merged result will be roughly 19 MB. You won't accidentally push a file over an email limit by combining it with something small. [Gmail and Outlook](https://support.google.com/mail/answer/6584) both cap attachments at 25 MB, and the actual usable limit before base64 encoding overhead is closer to 18 to 19 MB, but merging itself adds nothing to the total.

If the combined size is still over your limit after merging, run the file through the [Compress PDF tool](/compress-pdf). Bear in mind that compression works well on scanned documents and image-heavy PDFs, but can make text-only documents significantly larger because it rasterizes every page to JPEG. If your merged PDF is mostly text, splitting out the largest file or compressing the image-heavy portions separately will do more good.

## One thing to check before you merge a filled form

If any of your PDFs contain a filled-out form, merging will strip the form fields. The page content (your answers, stamps, checkboxes) may survive visually, but the underlying interactive layer is dropped. This is a limitation of how most JavaScript PDF libraries handle the [PDF format's AcroForm specification](https://en.wikipedia.org/wiki/PDF#AcroForms).

The fix is simple: flatten the form before merging. Flattening converts the interactive fields into static page graphics, so the values become part of the page itself and cannot be lost in a merge. Use the [Flatten PDF tool](/flatten-pdf) first, then bring the flattened copy into the merge.

If you're combining a cover letter (a regular PDF) with a filled application form and a supporting document, flatten the form first, then merge all three. The cover letter and supporting document don't need flattening because they have no fields.

## Which files work in Chrome?

Any standard PDF file works. Chrome's own rendering engine handles the file-picker step, so there's no special compatibility requirement. Files saved from Word, Google Docs, scanners, or other PDF tools all merge cleanly.

Very large files (over 100 MB each) may be slow because the merge runs on your device rather than a fast server. For typical documents, forms, and presentations, you won't notice any lag.

## A quick recap

Chrome itself can't merge PDFs. The cleanest way to do it in Chrome is to open a browser-based tool in a tab, add your files, and download the result. The merge runs on your device, nothing is uploaded, and there's no sign-up or extension required. Flatten filled forms before you merge, and compress the output if the total size is still over a file limit.
