## What to look for in a free PDF compressor

Three things separate a useful compressor from a frustrating one.

**No sign-up.** Any tool that demands an email address before letting you compress a file is adding friction for no good reason. Free, in-browser tools have no server costs to recover, so there's no business reason to gate the feature behind an account.

**In-browser processing.** When a tool compresses your file inside your browser tab rather than uploading it to a remote server, your document never leaves your device. This matters most for confidential files. Server-based tools aren't automatically unsafe, but you should know which type you're using.

**Multiple compression levels.** A single compression setting doesn't fit every situation. A scanned resume that needs to stay under 5 MB calls for something lighter than a 50-page photo brochure you're trying to squeeze below 1 MB. Tools that offer low, medium, and high settings let you pick the right trade-off between size and quality.

## Which PDF files actually get smaller when compressed?

This is the part most guides skip, and it's the most important thing to understand before you compress anything.

Browser-based PDF compression works by [rasterizing each page to a JPEG](https://en.wikipedia.org/wiki/Rasterisation). That approach works well when pages already contain photographs or scanned images, because converting a photo to a smaller JPEG genuinely reduces the data. It works poorly when pages contain mostly text, because text stored as vector glyphs is tiny to begin with, and converting it to a photograph of text adds data rather than removing it.

In testing, a 6-page image-heavy PDF at 913.4 KB compressed to 315.3 KB at Medium, a 65.5% reduction. The same approach on a 20-page text report starting at 23.5 KB produced a 1.4 MB output, roughly 60 times larger.

If your PDF contains mostly paragraphs, headings, and line art, compression will make it bigger, not smaller. Use it only on files with photos, scanned pages, or graphic-heavy slides.

## How much can free compression reduce file size?

For image-heavy PDFs, the results are meaningful. In our testing:

- **Medium setting:** a 913.4 KB photo deck compressed to 315.3 KB (65.5% smaller)
- **High setting:** same deck compressed to 175.6 KB (80.8% smaller)
- **Low setting:** same deck compressed to 703.5 KB (23% smaller)

The right level depends on what you need the file for. If it needs to stay readable for print, Medium is usually the safe choice. High gets the file smaller, but text and fine detail become harder to read at 100% zoom. For a document someone will read on screen only, High is workable.

## In-browser compression vs server-side: what's the difference?

Server-based compressors upload your file, process it on a remote machine, and send the result back. In-browser tools run the entire process inside your browser tab using WebAssembly, so the file bytes never reach any server.

For everyday documents, both approaches get the job done. For files containing contracts, medical records, or anything you'd hesitate to email to a stranger, in-browser processing is the safer choice. The file stays on your machine throughout.

## What if compressing makes the file larger?

If the compressed file is bigger than the original, the PDF is almost certainly text-based. The compressor rasterized the text into images, and that made the file larger rather than smaller.

For a text-heavy PDF that's too big to email or upload to a form, compression isn't the right fix. Try [splitting the PDF](/split-pdf) into smaller parts and sending them separately. Alternatively, upload the full file to a cloud storage service and share a link instead of an attachment. [Gmail caps attachments at 25 MB](https://support.google.com/mail/answer/6584), but lets you insert a Google Drive link for larger files without any size ceiling.

If the file is image-heavy and compression still isn't getting it small enough, try the High setting and start from the original file rather than the compressed version.

## Can you run the same PDF through the compressor twice?

No, and this is common advice that makes things worse. A second compression pass at the same level makes the file larger, not smaller.

In testing, feeding a compressed 315.3 KB file back through Medium compression produced a 598.9 KB output, nearly double the size. The already-rasterized pages get re-encoded, and re-encoding a JPEG that's already been compressed adds data rather than removing it.

If the first compression didn't get the file small enough, don't run it again. Go back to the original file and try the High setting instead. That approach brought the same 913.4 KB PDF down to 175.6 KB, far better than chaining two passes at a lower setting.
