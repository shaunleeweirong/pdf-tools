## Are free online PDF tools safe to use?

Free online PDF tools are safe when they process your file inside your browser, and risky when they upload it to a server. That distinction matters more than the tool's name, price, or popularity. If your document contains anything sensitive, knowing which category a tool falls into is the first thing to check.

## What actually happens when you use an online PDF tool

There are three categories of online PDF tools, and they handle your file very differently.

**Browser-only tools** use JavaScript or [WebAssembly](https://webassembly.org/) running directly in your browser tab. Your file is loaded into your device's memory, processed, and returned to you without ever touching an external server. Nothing is transmitted over the network. The tools on this site work this way: [Compress PDF](/compress-pdf), [Merge PDF](/merge-pdf), [Sign PDF](/sign-pdf), and the rest run entirely in your browser. You can verify this yourself with the network tab test described below.

**Ephemeral server tools** upload your file to a remote server, process it there, and (per their stated policy) delete both the input and output after a short window, typically one hour. The protection here is contractual rather than technical. A retention policy is a promise from the vendor, not a hard technical constraint. Backups, CDN edge caches, and log files can all outlive the "deleted" primary copy, and you have no independent way to verify that deletion actually happened.

**Persistent server tools** upload your file and keep it for the life of your account, or longer. Some explicitly state in their terms that uploaded files may be used to improve their product, train AI models, or be shared with partners. Their terms of service is worth reading before you upload anything you'd mind showing up in a training dataset.

## Which documents should never go to a server-based tool

The question isn't about file format. It's about what's inside. Treat these types of documents as off-limits for any tool that uploads to a server:

- Medical records, test results, and insurance documents
- Tax returns, bank statements, and pay stubs
- Legal contracts, NDAs, and settlement agreements
- Government-issued IDs, passports, and visa documents
- Signed agreements containing financial or personal details

If a document would cause real harm in the wrong hands, process it locally. Use a browser-based tool, or use offline software like [Ghostscript](https://www.ghostscript.com/) for command-line processing.

## Can an online PDF tool read your document's contents?

Yes, if it uploads your file. A server-based tool receives the full PDF, which includes all the text, images, and embedded metadata. Tools that offer optical character recognition (OCR) or AI-based editing are, by definition, parsing your content on their servers.

Browser-based tools work differently. Your browser executes the JavaScript locally, so the vendor's infrastructure never receives the file's contents. The same runtime environment that runs your bank's online calculator runs the PDF tool. In both cases, the data stays on your machine.

## How to confirm whether a tool is browser-based

Don't rely on marketing language alone. The reliable test takes about thirty seconds:

1. Open your browser's developer tools by pressing **F12** (or right-click anywhere on the page and choose "Inspect").
2. Click the **Network** tab.
3. Drop your PDF file into the tool's upload area.
4. Watch for outbound requests. Filter by "All" and look for a large POST request being sent to an external domain.

If you see your file being transmitted, the tool is server-based. A browser-only tool generates no outbound file transfer at all. You can also look for [WebAssembly (.wasm)](https://developer.mozilla.org/en-US/docs/WebAssembly) files loading when the page initializes. These compiled modules let PDF processing run in-browser without a server round-trip, and they're a reliable sign that the tool is doing its work locally.

## Does password-protecting a PDF help if you do need to upload?

[AES-256 encryption](https://en.wikipedia.org/wiki/Advanced_Encryption_Standard) makes the contents of a PDF unreadable to anyone who doesn't know the password, including a server that receives the file. Encrypting a document before uploading it to a server-based tool is a meaningful privacy step, because even if the file is retained, it's unreadable without the key.

Our [Protect PDF](/protect-pdf) tool does this locally in your browser using qpdf compiled to WebAssembly, so you can encrypt a file without transmitting it anywhere first.

Keep in mind that encryption covers the contents, not the fact of the file's existence. The server still logs your IP address, the upload timestamp, the file name, and any unencrypted metadata fields like the document title and author. If those details matter, browser-based processing is the only option that avoids them entirely.

## When merging or combining files before sharing

One common scenario is combining several documents into one PDF before emailing or uploading it somewhere. Our [Merge PDF](/merge-pdf) tool handles this in-browser, which means neither the individual files nor the combined result ever leaves your device.

One thing to know: merging strips interactive form fields from any filled-in PDF forms. If you've filled out a form and want to merge it with other documents, [flatten the form first](/flatten-pdf) so the values are burned into the page before merging. Otherwise the field data is lost, even though the page content appears intact.

## What to do if you already uploaded something sensitive

If you've uploaded a confidential document to a server-based service, here are your next steps:

1. Check their privacy policy for the stated retention window.
2. Submit a deletion request if the service offers one.
3. If you're in the EU, [GDPR Article 17](https://gdpr-info.eu/art-17-gdpr/) gives you the right to erasure. If you're in California, [CCPA](https://oag.ca.gov/privacy/ccpa) provides a similar right. Both require vendors to respond within a defined time window.
4. If the vendor doesn't respond or doesn't honor the request, contact your country's data protection authority.

The simplest approach is to use tools that don't upload in the first place. Pursuing a deletion request after the fact is harder than avoiding the upload to begin with.
