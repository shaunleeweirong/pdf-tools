## What makes a PDF file so large

Your PDF file is so large because of at least one of four things: embedded images, scanned pages, embedded font files, or hidden data left over from editing. Each cause needs a different fix, and the wrong fix (compression in particular) can make things considerably worse.

Here is what each cause looks like and how to confirm it before you do anything else.

## High-resolution images

Images are the biggest contributor to PDF file size in most cases. A page containing a full-bleed graphic or a high-resolution chart is mostly pixel data, and pixel data scales with dimensions and color depth.

Slide decks, marketing brochures, and product catalogs tend to be image-heavy for exactly this reason. If your PDF is 5 MB for a 10-page document, images are almost certainly the cause. Compression works well here: the pages are already rasterized, so re-encoding those pixels at lower JPEG quality directly reduces file size.

## Scanned documents

When you scan a paper document, each page is saved as a bitmap image, not as text. A single A4 page scanned at 300 dpi in color can easily run 1 to 2 MB. A 20-page scanned report can top 30 MB with no compression applied.

Scanned PDFs respond well to compression for the same reason as image-heavy files: the pages are images, and the compressor re-encodes them at reduced quality. The trade-off is that text in a scanned PDF is not selectable or searchable. It was never stored as text, only as a photograph of text.

## Embedded fonts

PDFs carry font files so they can render text identically on any device. A single font file is typically 100 to 500 KB. A document using four or five typefaces can easily add 1 to 2 MB of font data that has nothing to do with the number of pages or words.

Well-configured PDF exporters use [font subsetting](https://en.wikipedia.org/wiki/Font#Embedding_and_subsets), embedding only the specific characters that appear in the document rather than the full font. Poorly configured exporters embed the full font, and some applications embed multiple copies. If a small Word document becomes a surprisingly large PDF, fonts are often the culprit.

[Microsoft's PDF export settings](https://support.microsoft.com/en-us/office/save-or-convert-to-pdf-or-xps-format-in-office-desktop-apps-d85416c5-7d77-4fd6-a216-6f4bf7c7c110) include an "Optimize for" option. Choosing "Minimum size (publishing online)" instead of "Standard" typically produces a noticeably smaller file by adjusting both image handling and font settings.

## Hidden elements

A PDF can carry content that does not appear on any visible page. Annotation data from review cycles, revision history embedded by InDesign, form fields that were never removed, and file attachments can all add unexpected size. This comes up most with files that have been through multiple rounds of editing or commenting in a PDF editor.

Flattening the document removes interactive elements and merges annotations into the page content. Use the [Flatten PDF](/flatten-pdf) tool if a document has accumulated a lot of review history or interactive form fields.

## Why compression can make your PDF larger

This is the thing most guides get wrong, so it is worth being direct: **compression that rasterizes pages will make text-only PDFs dramatically larger, not smaller.**

Most online compression tools, including our [Compress PDF](/compress-pdf) tool, work by rendering each page as a JPEG image and then assembling those images into a new PDF. That works well when the page is already a photo or a scan, because you are trading pixel quality for file size. It works badly on text-based pages.

A page of body text stored as vector data is tiny. The text is described as character codes and font references, not as pixels. When you rasterize that page to a JPEG, you replace compact vector data with a pixel-by-pixel photograph of the same content.

We tested this with our own tool. A 20-page text report at 23.5 KB grew to 1.4 MB after medium compression, an increase of about 60 times. A mostly-text document with a small logo grew from 35.0 KB to 171.2 KB. An image deck at 913.4 KB, on the other hand, dropped to 315.3 KB at medium quality, a reduction of 65.5%.

**The pattern is consistent:** if the large thing in your PDF is images or scanned pages, compression helps. If it is fonts, revision history, or vector text, compression will make the file larger.

## How to tell which kind of PDF you have

Open the PDF and zoom in to 400% on a block of text. If the text stays sharp at any zoom level, the pages are vector-based. If it becomes blocky or pixelated, the pages are rasterized images.

File size per page is another rough check. Divide the total file size by the page count. Under 100 KB per page usually indicates vector content. Above 500 KB per page almost always means images or scans.

## The fastest free fix for each situation

**Image-heavy or scanned PDF:** Use the [Compress PDF](/compress-pdf) tool. Start at Medium quality. If the result is still too large, go back to your original and try High. Do not run compression twice: in testing, a second medium pass on an already-compressed image deck grew the file from 315.3 KB to 598.9 KB rather than shrinking it. If you need a smaller file than High produces, you have reached the quality floor for this approach.

**Text document that exported too large:** Compression is not the right tool. Instead:

- Re-export from the source application (Word, Google Docs, InDesign) with lower image quality or the "for screen" / "minimum size" setting.
- Use [Delete Pages](/delete-pages) to remove pages you do not need to share.
- Use [Split PDF](/split-pdf) to break a long document into smaller files. [Gmail and Outlook both cap email attachments at 25 MB](https://support.google.com/mail/answer/6584), so splitting a large report into sections keeps each part well within that limit without any quality loss.

**Document with annotations or form fields:** Use [Flatten PDF](/flatten-pdf) before sharing. It locks annotations into the page and strips the interactive layer, which can bring down the file size for documents that have been through several rounds of reviewing.

**Scanned document that also needs searchable text:** Compression will shrink the file, but the text will remain non-selectable pixels. For a searchable result, you need OCR first. Our tools do not include OCR, so that step needs to happen in a separate app before you bring the file here to compress.

## A more reliable approach than trial and error

Check the file size per page and zoom in on text before you do anything. That two-step look tells you whether pages are vector or raster and whether compression is likely to help or hurt.

Text PDFs stay small by staying text. The right answer for a bloated text document is usually a better export setting, not a compressor. Image and scan PDFs get smaller through compression, and our free in-browser tool handles that without uploading your files to a server.
