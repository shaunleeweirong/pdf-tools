Flattening a PDF means converting every interactive element, including form fields, checkboxes, annotations, comments, and signature images, into permanent, static page content. The end result looks identical to the original, but the document no longer has any editable structure underneath.

If you just need to flatten a file, the free [Flatten PDF tool](/flatten-pdf) handles it in your browser with no sign-up required.

## What actually changes when you flatten a PDF

Think of a PDF as having two layers on top of each other. The bottom layer is the static page content: text, images, backgrounds, and borders. The top layer holds anything interactive: the text boxes where you typed a name, the checkbox you ticked, a comment your colleague left in the margin, a red stamp someone added.

Until you flatten the file, those two layers are separate data structures inside the document. Some software reads only the bottom layer. That is why a form you carefully filled out on your screen can show up completely blank when a court system or an older PDF viewer opens it.

Flattening paints the top layer onto the bottom layer, permanently. Everything that was interactive is now just ink on the page. Nobody can click the fields, edit the text, or remove the annotations. The [PDF specification](https://en.wikipedia.org/wiki/PDF) calls these interactive elements "annotations," and the process of merging them down is known as annotation flattening.

The elements commonly affected include:

- **Form fields** (text boxes, checkboxes, radio buttons, dropdown menus)
- **Comments and sticky notes** added by reviewers
- **Ink annotations and drawing markups**
- **Stamps** (APPROVED, DRAFT, CONFIDENTIAL, and custom ones)
- **Signature appearances** (the visible drawing or image of a signature)
- **Optional content layers** (sometimes called PDF layers, used in technical drawings)

One important note about digital signatures: flattening a file that carries a cryptographic digital signature will break that signature's verification because the document bytes change. If the signature's legal validity matters, do not flatten. Merge documents first, then apply any signatures at the end.

## What does NOT change when you flatten

The visual appearance of the page is identical before and after. Text stays in place. Images stay in place. The filled-in form values, highlights, and comments all remain visible, they just cannot be moved, changed, or deleted anymore.

File size can go up or down slightly depending on how much annotation data the original file contained, but flattening is not a compression tool. If reducing file size is your goal, that requires a different operation.

## When should you flatten a PDF?

**Before merging documents.** When you [Merge PDF](/merge-pdf) files, the merge process removes form field structure from the output. We tested this directly: a PDF with a filled text field came out of the merge with zero form fields remaining. If you want your filled values to survive the merge, flatten the form first so those values become permanent page content before you combine the files.

**Before submitting to a court or government portal.** Many e-filing systems, including the federal courts' CM/ECF system, require flattened PDFs. An unflattened form can look complete on your screen but appear empty to the filing system because the field values live in a data layer the system does not read.

**Before printing.** Printers render the static page layer. Annotation layers sometimes print and sometimes do not, depending on print settings. Flattening guarantees that everything visible on screen also shows up on paper.

**Before sharing a final document.** If you are sending a form to someone who should read it but not fill it out or change anything, flattening prevents accidental edits. This applies to invoices, contracts you have already signed, and any document where the content is final.

**After signing with a drawn signature.** If you drew your signature on a PDF and the signature is stored as an annotation, flattening locks that signature into the page so it cannot be repositioned or deleted by a recipient.

## Is flattening the same as compressing?

No. These are two entirely different operations and they are frequently confused.

Compression reduces file size by encoding image data more efficiently. Our compressor, for instance, rasterizes each page to JPEG format, which works well on image-heavy files and actually makes text-only PDFs larger (a 23.5 KB text report grew to 1.4 MB after compression, because vector text is compact and JPEG photographs of text are not).

Flattening does not re-encode anything. It removes the interactive structure and writes the formerly separate annotation layer into the static page. File size may shift by a small amount, but flattening is not a tool for shrinking files.

If you are trying to reduce file size, use a compress tool. If you are trying to lock content or prepare a document for submission, use flatten.

## Is flattening reversible?

No. Once a file is flattened, the interactive elements are gone from that copy. There is no "undo" after the fact. The original structure is not stored anywhere in the output.

Always keep the original file before you flatten. If you later need to change a form field value or reply to a comment, you will need the pre-flatten version.
