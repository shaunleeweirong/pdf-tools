You can password protect a PDF on Android for free, right in your browser, without installing any app or creating an account. Open the [Protect PDF tool](/protect-pdf) on any Android browser, pick your PDF, type a password, and download the encrypted result. The whole thing takes under a minute.

Android's built-in tools don't cover this. The Files app, Google Drive, and Chrome's PDF viewer can all open password-protected files, but none of them can lock a PDF you haven't protected yet. That step needs either a dedicated app or an in-browser tool.

## How to protect a PDF on Android in your browser

This works in Chrome, Firefox, Samsung Internet, and any other modern Android browser.

1. Open the [Protect PDF tool](/protect-pdf) on your Android device.
2. Tap **Choose file** and pick the PDF from your storage, Downloads folder, or Google Drive.
3. Type a password. It can be any combination of letters, numbers, and symbols.
4. Tap **Protect** and wait a few seconds.
5. Tap **Download** to save the encrypted file back to your device.

That's it. The result is a standard PDF that any reader (Adobe Acrobat, Chrome, Samsung's viewer, WPS Office) will prompt for a password before opening.

The tool runs entirely in the browser tab. Your PDF is never uploaded to a server.

## What type of encryption does it apply?

The tool uses [AES-256 encryption](https://en.wikipedia.org/wiki/Advanced_Encryption_Standard), which the [PDF specification (ISO 32000)](https://www.iso.org/standard/75839.html) lists as one of the two supported encryption algorithms for PDF files. AES-256 is the same standard used to protect banking transactions and classified government data. Without the correct password, the contents of the file are mathematically unreadable.

Every attempt with a wrong password is rejected. There's no "try many passwords quickly" shortcut built into the PDF format itself, though brute-force tools exist for very short or common passwords. A longer, less predictable password is meaningfully harder to break.

## Choosing a password that actually protects the file

A short, common password ("1234", "password", the recipient's name) offers very little real protection. A few practical suggestions:

- **Use at least 12 characters.** Length matters more than complexity alone.
- **Mix in numbers or symbols.** "quarterly-report-2026!" is much better than "report".
- **Don't reuse a password you use elsewhere.** If this PDF ends up in the wrong hands, you don't want anything else exposed.
- **Note it somewhere secure.** AES-256 encryption cannot be reversed without the password. If you lose it, the file is permanently inaccessible.

## Does adding a password change the file size?

Barely. Encryption overhead is roughly 1 KB, regardless of the original file size. In testing, a 23.5 KB text report grew to 24.6 KB (a 4.8% increase). A 913.4 KB image deck grew to 914.4 KB (a 0.1% increase). In practical terms, a password-protected PDF is no harder to email than the original.

## Does it work on all Android browsers?

The Protect PDF tool works on any Android browser that supports modern web APIs: Chrome, Firefox, Samsung Internet, Brave, and Edge for Android all qualify. If your Android device is running Android 7 or later (released in 2016), the browser on it is supported. Older devices may have outdated WebViews that don't work with some browser-based tools, but that's increasingly rare.

Samsung Internet is worth a mention specifically because it has a built-in download manager and a native PDF viewer, which makes the save-and-check workflow smooth. But any browser gets the job done the same way.

## How to remove the password from a PDF on Android

If you want to strip the password later, use the [Unlock PDF tool](/unlock-pdf). Enter the password you set originally, and the tool removes the encryption. The unprotected output comes back within a few bytes of the original file size, so the process is effectively lossless in size terms.

This works for PDFs you protected yourself. It won't help with files where you don't know the password.

## What about merging a protected PDF?

One thing to watch: if you [merge a protected PDF](/merge-pdf) with another file, the password protection is stripped in the process. The merged output is not protected. If you need the final merged document to be encrypted, protect it after merging, not before.

Similarly, if you have a PDF with filled form fields that you want to merge, [flatten it first](/flatten-pdf) to lock the field values into the page, since merging strips interactive form fields.

## When does a password actually help?

A PDF password limits who can open the file. It makes sense for:

- **Documents shared via email or chat** that contain personal or sensitive information (tax documents, signed contracts, medical records).
- **Files stored in a shared cloud folder** where you want an extra layer of access control.
- **Drafts or confidential reports** sent to a specific person who you can share the password with separately.

It doesn't prevent someone from screenshotting or photographing pages after they've entered the correct password. If you need to stop a recipient from capturing content at all, that requires a different approach (and there's no reliable technical way to do it with standard PDFs).

A password is also not a substitute for thinking carefully about who you're sharing a file with. It adds friction; it doesn't make sharing with the wrong person harmless.

## Comparing browser-based and app-based protection on Android

Both approaches have the same end result: an AES-256-encrypted PDF. The main differences come down to privacy and convenience.

**Browser-based (like the Protect PDF tool):** Runs locally, no upload, no account required. Works on any device with a modern browser. Good for occasional use.

**Dedicated Android app:** Usually requires downloading from the Play Store and may ask for permissions (storage access, and sometimes more). Some apps work offline; others route files through their servers. Read the privacy policy before you use one.

For most people protecting an occasional document, the browser-based route is the simpler choice.
